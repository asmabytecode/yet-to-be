# 0007. Гнучкий RBAC і власник через серверну команду

- Статус: прийнято
- Дата: 2026-11-27

## Контекст

Ролі в адмінці різнитимуться між командами (редактор, модератор, підтримка). Жорстко зашиті ролі
вимагали б релізу на кожну зміну, а видача прав через HTTP — найпривабливіша ціль для атаки.

## Рішення

- Каталог прав (`PERMISSIONS` у `packages/shared`) — у коді; ролі (`roles`, `role_permissions`,
  `user_roles`) — у БД, створюються й редагуються в адмінці.
- Системні ролі `owner` і `admin` створює міграція; їх не можна видалити чи змінити через API.
- Антиескалація: видати роль або створити роль можна лише з правами, які є в того, хто видає (`covers`).
  Змінювати власні ролі й блокувати себе заборонено.
- Власника (`owner`, вимагає MFA) призначає лише серверна команда `pnpm owner:grant <email>`
  (у контейнері — `node dist/cli/owner-grant.js`). HTTP-шляху до ролі власника немає.
- Глобальний `PermissionGuard` після JWT: права → обов'язкова MFA ролі → свіжий step-up для
  критичних дій (`@RequireStepUp`, 5 хвилин).
- UI лише ховає недоступне; сервер перевіряє кожен запит сам.

## Наслідки

- Нова роль — без релізу; нове право — лише з релізом (код має знати, що воно означає).
- Компрометація адмін-акаунта не дає стати власником.

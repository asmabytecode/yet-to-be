# Політика безпеки

## Підтримувані версії

Виправлення безпеки випускаються для останнього релізу (`v*.*.*`) і гілки `main`.

## Як повідомити про вразливість

**Не створюйте публічний issue.** Скористайтеся приватним каналом GitHub:
**Security → Report a vulnerability** у цьому репозиторії (Private vulnerability reporting).

Опишіть:

- уразливий компонент і версію (тег або commit);
- кроки відтворення або proof of concept;
- можливий вплив (які дані чи дії під загрозою).

## Що далі

| Етап                        | Термін             |
| --------------------------- | ------------------ |
| Підтвердження отримання     | до 3 робочих днів  |
| Оцінка та план виправлення  | до 10 робочих днів |
| Виправлення critical / high | до 30 днів         |

Після випуску виправлення ми публікуємо GitHub Security Advisory і, за бажанням автора, згадуємо його.

## Область

У межах: код цього репозиторію (API, фронтенд, Docker/Nginx-конфігурація, workflows).
Поза межами: DoS об'ємом трафіку, соціальна інженерія, вразливості сторонніх сервісів (Google, GitHub),
знахідки автоматичних сканерів без підтвердженого впливу.

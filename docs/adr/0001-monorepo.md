# 0001. Монорепо на pnpm workspaces + Turborepo

- Статус: прийнято
- Дата: 2026-11-26

## Контекст

API (NestJS) і фронтенд (React) мають спільні контракти: схеми запитів, DTO, коди помилок.
Якщо тримати їх у різних репозиторіях, контракт дублюється і розходиться, а зміна API потребує
синхронних PR у двох місцях.

## Рішення

Один репозиторій:

- `apps/api`, `apps/web` — застосунки;
- `packages/shared` — Zod-схеми й типи, які використовують обидві сторони;
- `packages/tsconfig`, `packages/eslint-config` — спільні конфігурації.

pnpm workspaces керує залежностями (один lockfile, суворий `node_modules` без фантомних залежностей).
Turborepo запускає задачі в правильному порядку (`^build`) і кешує результати.

## Наслідки

- Зміна контракту — один PR, typecheck одразу ловить несумісність на обох сторонах.
- CI перевіряє все разом; при рості команди додається Turborepo remote cache і CODEOWNERS по модулях.
- Docker-образи збираються з кореня монорепо (`pnpm deploy` для API), тому `.dockerignore` важливий.
